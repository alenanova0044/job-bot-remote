# job-bot-alena

Бот, который ищет операционные вакансии под твой профиль (RU-рынок, part-time/проектная занятость,
health/edtech/психология/НКО в приоритете) в трёх источниках — hh.ru (официальный API), Telegram-каналы,
RSS джоб-бордов — оценивает по criteria.json и присылает подходящие в Telegram-группу.

Архитектура такая же, как у бота Димы (job-bot-dima): без веб-сервера, один скрипт `bot.py`,
запускается по расписанию через Railway Cron, состояние (что уже отправляли) хранится в файле
на подключённом Volume.

## Что нужно получить перед деплоем

### 1. Telegram-бот (для отправки сообщений)
1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → следовать инструкциям
2. Получить `TELEGRAM_BOT_TOKEN`

### 2. Группа для вакансий
1. Создать приватную Telegram-группу или канал (например «Вакансии для меня»)
2. Добавить туда бота как администратора
3. Получить `TELEGRAM_GROUP_ID` — самый простой способ: написать что-нибудь в группу,
   потом открыть `https://api.telegram.org/bot<TOKEN>/getUpdates` в браузере и найти `"chat":{"id": ...}`
   (id для групп обычно отрицательный, например `-1001234567890`)

### 3. Доступ для чтения Telegram-каналов (Telethon)
Обычный бот НЕ может читать чужие публичные каналы за тебя — только личный аккаунт.
1. Зайти на https://my.telegram.org под своим номером
2. API Development Tools → создать приложение → получить `TG_API_ID` и `TG_API_HASH`
3. Локально на своём компьютере (не на Railway!) выполнить:
   ```bash
   pip install telethon
   python3 telegram_login.py
   ```
   Ввести `TG_API_ID`, `TG_API_HASH`, залогиниться номером телефона (придёт код в Telegram) —
   скрипт напечатает `TG_SESSION_STRING`. Сохранить его — это как пароль от аккаунта, никому не показывать.

### 4. hh.ru
Ничего получать не нужно — `api.hh.ru` открытый и бесплатный, без ключей.

## Деплой — GitHub Actions (бесплатно, рекомендуется)

Railway с 2023 года не бесплатен по-настоящему (30-дневный триал → дальше от $1/мес и лимит
1 проект на аккаунт), а этому боту постоянный сервер и не нужен — он просто разово запускается
по расписанию. GitHub Actions для этого подходит идеально и остаётся бесплатным без ограничения
по времени (для приватного репозитория — 2000 бесплатных минут/месяц, боту хватает пары минут в месяц).

1. Создать **приватный** репозиторий на GitHub, залить туда всю эту папку целиком (включая `.github/workflows/run-bot.yml` и `data/seen_jobs.json`)
2. Settings → Secrets and variables → Actions → New repository secret — добавить по одному:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_GROUP_ID`
   - `TG_API_ID`
   - `TG_API_HASH`
   - `TG_SESSION_STRING`
3. Вкладка **Actions** → разрешить workflows, если GitHub спросит
4. Settings → Actions → General → Workflow permissions — выбрать **Read and write permissions**
   (нужно, чтобы бот мог сам коммитить обновлённый `data/seen_jobs.json` обратно в репозиторий)
5. Готово — бот будет запускаться каждые 2 часа сам. Проверить сразу, не дожидаясь расписания:
   вкладка Actions → job-bot-alena → Run workflow (кнопка справа, это и есть `workflow_dispatch`)

Расписание — строка `cron: "0 */2 * * *"` в `.github/workflows/run-bot.yml`, меняется как обычный cron.

## Альтернатива — Railway (если предпочитаешь)

Тот же код прекрасно работает и на Railway, просто это будет стоить от $1–5/мес после триала,
и один бесплатный аккаунт не потянет одновременно бота Димы и этого — либо второй аккаунт,
либо оплаченный план. Если решишь так — шаги те же, что раньше: Deploy from GitHub repo,
Variables (те же 5 секретов + `STORAGE_PATH=/data/seen_jobs.json`), Volume на `/data`,
Cron Schedule `0 */2 * * *`, Start Command `python3 bot.py`.

## Локальный тест перед деплоем

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_GROUP_ID=...
export TG_API_ID=...
export TG_API_HASH=...
export TG_SESSION_STRING=...
python3 bot.py
```

Если переменные не заданы — бот не упадёт, а просто напечатает найденные вакансии в консоль
вместо отправки (удобно для проверки, что критерии работают правильно).

## Как донастраивать под себя

Всё живёт в `criteria.json`, код трогать не нужно:
- `roles_keywords` — какие роли ищем
- `stop_words` / `stop_roles` — что сразу отсеиваем (ритейл-конвейер, продакшн, продажи и т.п.)
- `priority_industry_keywords` — health/edtech/психология/НКО — бонус к скору
- `salary_min_*` — денежный порог
- `telegram_channels` — список каналов без @, добавлять/убирать свободно
- `rss_sources` — любые открытые RSS-ленты
- `min_score_to_send` — порог 0–10, ниже которого вакансия не отправляется (сейчас 5)

## Что бот НЕ делает (осознанно)

- Не откликается на вакансии сам — только присылает и даёт ссылку, отклик всегда руками
- Не использует платный ИИ-скоринг — правило-based логика в `scorer.py`, бесплатно и предсказуемо.
  Если увидишь, что фильтр ошибается — правь `scorer.py` или `criteria.json`, а не переписывай архитектуру
- Не хранит резюме/сопроводительные — для этого у тебя уже есть готовый CV, отдельная генерация не нужна,
  но если понадобится — можно взять за основу подход `build_docs.py` из проекта Димы
